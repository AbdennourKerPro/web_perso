Find Minimum in Rotated Sorted Array

16 Oct 2026 #153 · Medium ↗ dichotomie tableau trié roté python

Le problème

Un tableau trié de n entiers distincts a été roté entre 1 et n fois vers la droite. Renvoyer son minimum en O(log n). Pour [3,4,5,1,2], la réponse est 1 ; pour [4,5,6,7,0,1,2], c'est 0 ; pour [11,13,15,17] (rotation de n fois, donc tableau inchangé), c'est 11.

L'idée clé

Le tableau est formé de deux segments croissants, et le minimum est le premier élément du second : c'est là que la suite « casse ». Une dichotomie permet de localiser cette cassure. Pour un indice mid, on regarde de quel côté du minimum il se trouve. L'invariant est simple : le minimum reste toujours dans l'intervalle [l, r], et la boucle while l < r s'arrête sur lui.

Solution 1 : ta première version (dichotomie, comparaison à nums[l])

solution_1.py

class Solution:
    def findMin(self, nums: list[int]) -> int:
        n = len(nums)
        l = 0
        r =len(nums)-1

        while l < r:
            mid = (l+r)// 2

            if nums[l] < nums[r]:
                return nums[l]
            if nums[mid] >= nums[l]:
                l = mid + 1
            else:
                r = mid

        return nums[l]

Correcte. Le retour anticipé est valable : si nums[l] < nums[r], le segment [l, r] n'a aucune cassure, donc nums[l] en est le minimum. Sinon, si nums[mid] >= nums[l], la moitié gauche est croissante et le minimum est à droite de mid. La variable n n'est pas utilisée.

Solution 2 : ta deuxième version (linéaire)

solution_2.py

class Solution:
    def findMin(self, nums: list[int]) -> int:
        if len(nums)==1:
            return nums[0]
        left, right = 0, len(nums)-1
        if nums[left]<nums[right]:
            return nums[left]
        while nums[left] < nums[left+1] and nums[right] > nums[right-1]:
            left+=1
            right-=1
        if  nums[left] > nums[left+1]:
            return nums[left+1]
        if  nums[right] < nums[right-1]:
            return nums[right]

Ici, les deux pointeurs avancent vers le centre tant que les deux bords restent croissants, et la première cassure donne la réponse. C'est correct pour des valeurs distinctes (testé sur 5 000 rotations aléatoires), mais la contrainte O(log n) n'est pas respectée : la cassure peut se trouver au milieu, et il faut alors environ n/2 pas. Le if len(nums)==1 est indispensable, sinon nums[left+1] sort du tableau. Enfin, si les valeurs ne sont pas distinctes, la fonction se termine sans return et renvoie None.

Solution 3 (plus usuelle) : comparaison à nums[r]

La version canonique compare nums[mid] à nums[r], et non à nums[l]. Si nums[mid] > nums[r], la cassure est entre mid et r, donc le minimum est à droite de mid. Sinon, le segment [mid, r] est croissant : le minimum est en mid ou à gauche, on garde donc r = mid. Plus besoin de cas particulier pour un segment non roté.

solution_3.py

class Solution:
    def findMin(self, nums: list[int]) -> int:
        l, r = 0, len(nums) - 1
        while l < r:
            mid = (l + r) // 2
            if nums[mid] > nums[r]:
                l = mid + 1
            else:
                r = mid
        return nums[l]

Vérification

Les trois versions ont été comparées au minimum calculé directement sur 5 000 rotations aléatoires de tableaux de 1 à 12 valeurs distinctes : toutes donnent le bon résultat. Avec doublons (problème #154), elles se trompent dans certains cas, et ta deuxième version renvoie même parfois None.

À retenir

  • Un tableau trié roté est fait de deux segments croissants : le minimum est la cassure.
  • Comparer nums[mid] à nums[r] donne directement le côté du minimum, sans cas particulier.
  • Maintenir l'invariant « le minimum est dans [l, r] » rend la boucle simple à prouver.
  • Une solution linéaire peut être correcte, mais elle ne répond pas à la contrainte de l'énoncé.
  • Avec doublons (#154), la comparaison ne suffit plus : quand nums[mid] == nums[r], on réduit r d'un cran.

Subarray Sum Equals K

16 Oct 2026 #560 · Medium ↗ somme préfixe hashmap python

Le problème

Étant donné un tableau nums d'entiers (éventuellement négatifs) et un entier k, compter le nombre de sous-tableaux contigus et non vides dont la somme vaut k. Pour [1,1,1] et k = 2 : 2 (les deux paires adjacentes).

L'idée clé

Notons S[i] la somme des i premiers éléments (S[0] = 0). La somme du sous-tableau nums[i..j] vaut S[j+1] − S[i]. Il s'agit donc de compter les paires de préfixes (S[i], S[j+1]) telles que S[j+1] − S[i] = k. Pour chaque nouveau préfixe, il suffit de savoir combien de préfixes précédents valent S − k, ce qu'une table de hachage donne en O(1).

Déroulé sur [1,1,1], k = 2 avec la solution 1 : à i = 2, S − k = 0 est présent une fois (le préfixe vide), ce qui compte le sous-tableau [1,1].

Solution 1 : mon code

Ma version, qui suit exactement l'idée ci-dessus. Les print de débogage ont été retirés : ils affichaient à chaque exécution le tableau des préfixes et la table, ce qui pèse sur les grands tests.

solution_1.py

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        freq = {0:1}
        n=len(nums)
        res = 0
        cum = [0]*(n+1)
        for i in range(1,n+1):
            cum[i] = cum[i-1] + nums[i-1]
            if cum[i] - k in freq:
                res+=freq[cum[i] - k]
            freq[cum[i]] = freq.get(cum[i], 0) + 1
        return res

Point important : le test cum[i] - k in freq se fait avant d'ajouter cum[i] à la table. Sinon, avec k = 0, chaque élément se compterait lui-même comme un sous-tableau vide. La table est initialisée à {0: 1} pour compter les sous-tableaux qui commencent au tout début du tableau.

Solution 2 : somme courante, sans tableau

Le tableau cum n'est jamais réutilisé après l'itération : une variable total suffit, et la boucle peut parcourir nums directement. C'est la forme la plus courante en entretien.

solution_2.py

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        freq = {0: 1}
        total = res = 0
        for x in nums:
            total += x
            res += freq.get(total - k, 0)
            freq[total] = freq.get(total, 0) + 1
        return res

Les deux versions renvoient le même résultat que l'énumération brute-force de tous les sous-tableaux, sur 3 000 tableaux aléatoires contenant des valeurs négatives et nulles. Les exemples de LeetCode donnent 2 pour [1,1,1] et k = 2, et 2 pour [1,2,3] et k = 3.

Complexité

Temps O(n) : un seul passage, avec des insertions et recherches moyennes en O(1) dans le dictionnaire. Espace O(n) dans le pire cas (tous les préfixes distincts). La solution 2 garde le même temps mais évite le tableau cum : l'espace est alors dominé par la table de hachage. La version naïve, qui teste chaque sous-tableau, est en O(n²).

À retenir

  • Somme de sous-tableau = différence de deux préfixes : compter des paires plutôt que parcourir des sous-tableaux.
  • Interroger la table avant d'y insérer le préfixe courant (cas k = 0).
  • Initialiser avec {0: 1} pour le préfixe vide.
  • Pourquoi pas une fenêtre glissante ? Elle suppose que la somme croît quand on élargit la fenêtre, ce qui n'est plus vrai avec des négatifs. La table de hachage ne fait pas cette hypothèse.
  • Variante à connaître : Subarray Sums Divisible by K (#974), où l'on compte les préfixes ayant le même reste modulo k.

Combination Sum II

16 Oct 2026 #40 · Medium ↗ backtracking doublons python

Le problème

Étant donnés des candidates pouvant contenir des doublons et une cible, renvoyer toutes les combinaisons uniques dont la somme vaut la cible. Chaque candidat ne peut être utilisé qu'une seule fois. Pour [10,1,2,7,6,1,5] et une cible de 8 : [[1,1,6],[1,2,5],[1,7],[2,6]].

L'idée clé

Deux difficultés à combiner :

  • Chaque élément une seule fois : la récursion repart de i + 1, et non de i comme dans Combination Sum.
  • Éviter les doublons de résultat : si deux valeurs égales sont proposées au même niveau de la récursion, choisir l'une ou l'autre donne le même ensemble. On trie donc candidates, et on ignore une valeur identique à la précédente parmi les frères.

Solution

Mon code est déjà la version usuelle de ce problème.

solution.py

class Solution:
    def combinationSum2(self, candidates: list[int], target: int) -> list[list[int]]:
        res = []
        candidates.sort()

        def backtrack(start, target, path):
            if target == 0:
                res.append(list(path))
                return
            if target < 0:
                return

            for i in range(start, len(candidates)):
                if start < i and candidates[i] == candidates[i-1]:
                    continue

                path.append(candidates[i])
                backtrack(i+1, target - candidates[i], path)
                path.pop()

        backtrack(0, target, [])
        return res

La condition start < i est le point délicat. Elle ne saute que les valeurs identiques au même niveau de l'arbre (les « frères »), pas celles qui sont déjà dans le chemin. Avec i > 0 à la place, [1,1,2] et une cible de 2 donnent [[2]] au lieu de [[1,1],[2]] : le second 1 est sauté alors qu'il est nécessaire. J'ai vérifié ce cas et les deux exemples de LeetCode, ainsi qu'une comparaison à une énumération brute-force sur quelques centaines de tableaux aléatoires avec doublons.

Complexité

Temps O(2N · N) dans le pire cas, où N = len(candidates) : chaque élément est pris ou non, et chaque combinaison trouvée est copiée. Le tri ajoute O(N log N). Espace auxiliaire O(N) pour la pile de récursion.

À retenir

  • Doublons + « chaque élément une fois » : trier, puis sauter les frères identiques (start < i).
  • Le piège classique est de comparer à i > 0, qui supprime aussi des combinaisons valides.
  • Même idée que Subsets II (#90).

Combination Sum

16 Oct 2026 #39 · Medium ↗ backtracking python

Le problème

Étant donnés des candidates distincts et une cible, renvoyer toutes les combinaisons uniques dont la somme vaut la cible. Un même candidat peut être utilisé autant de fois qu'on veut. Pour [2,3,6,7] et une cible de 7 : [[2,2,3],[7]].

L'idée clé

C'est le patron de Subsets, avec deux différences. D'abord, comme un élément peut être réutilisé, la récursion repart de i et non de i + 1. Ensuite, on descend seulement tant que la somme ne dépasse pas la cible. Le paramètre start impose des indices croissants : on produit [2,3] mais jamais [3,2], qui est la même combinaison.

Solution 1 : mon code

solution_1.py

class Solution:
    def combinationSum(self, candidates: list[int], target: int) -> list[list[int]]:
        res = []

        def backtrack(start, target, path):
            if target == 0:
                res.append(list(path))
                return

            if target < 0:
                return

            for i in range(start, len(candidates)):
                path.append(candidates[i])
                backtrack(i, target - candidates[i], path)
                path.pop()
        backtrack(0, target, [])
        return res

Correct. Le cas target < 0 coupe une branche, mais la boucle essaie tous les candidats même lorsqu'ils dépassent déjà le reste : ces appels meurent immédiatement, sans effet sur le résultat. C'est ce que corrige la version suivante.

Solution 2 (plus usuelle) : tri et élagage

En triant candidates, dès qu'un candidat dépasse le reste, tous les suivants le dépassent aussi : on peut arrêter la boucle avec break. Le reste fonctionne sans cas négatif, puisque la récursion n'est appelée qu'avec des candidats qui tiennent dans le reste.

solution_2.py

class Solution:
    def combinationSum(self, candidates: list[int], target: int) -> list[list[int]]:
        candidates = sorted(candidates)
        res, path = [], []

        def backtrack(start, remaining):
            if remaining == 0:
                res.append(path[:])
                return
            for i in range(start, len(candidates)):
                if candidates[i] > remaining:
                    break
                path.append(candidates[i])
                backtrack(i, remaining - candidates[i])
                path.pop()

        backtrack(0, target)
        return res

Les deux versions renvoient les mêmes combinaisons, comparées à une énumération brute-force sur quelques centaines de cas aléatoires. La seconde explore moins de branches, et son code est plus court.

Complexité

Avec N candidats, le plus petit M et la cible T : la profondeur est au plus T / M, chaque niveau a au plus N branches. Temps O(NT/M · N) dans le pire cas (copie des combinaisons comprise), espace auxiliaire O(T / M) pour la pile et path.

À retenir

  • Réutilisation illimitée : la récursion repart de i, et non de i + 1.
  • Des indices croissants (start) suppriment les permutations d'une même combinaison.
  • Trier puis break élague la boucle dès qu'un candidat dépasse le reste.
  • Variantes à connaître : Combination Sum III (#216), avec un nombre fixé d'éléments distincts de 1 à 9, et Combination Sum IV (#377), qui compte les séquences ordonnées et se résout par programmation dynamique.

Permutations

16 Oct 2026 #46 · Medium ↗ backtracking python

Le problème

Étant donné un tableau nums d'entiers distincts, renvoyer toutes ses permutations, dans n'importe quel ordre. Pour [1, 2, 3], il y en a 3! = 6.

L'idée clé

On remplit la permutation position par position : à chaque étape, on choisit un élément pas encore utilisé. Contrairement à Subsets, l'ordre compte, donc on repart de tous les indices à chaque niveau (et pas seulement de ceux après start) : il faut alors un moyen de savoir quels éléments sont déjà pris.

[]
├─ [1]
│   ├─ [1, 2] ─ [1, 2, 3] ✓
│   └─ [1, 3] ─ [1, 3, 2] ✓
├─ [2]
│   ├─ [2, 1] ─ [2, 1, 3] ✓
│   └─ [2, 3] ─ [2, 3, 1] ✓
└─ [3]
    ├─ [3, 1] ─ [3, 1, 2] ✓
    └─ [3, 2] ─ [3, 2, 1] ✓

Solution 1 : tableau used et backtracking

Ma version, qui est aussi la formulation de référence : un tableau used marque les indices déjà placés dans path ; on choisit, on explore, puis on annule les deux.

solution_1.py

class Solution:
    def permute(self, nums: list[int]) -> list[list[int]]:
        used = [0]*len(nums)
        res = []
        def backtrack(used, path):
            if len(path) == len(nums):
                res.append(list(path))
                return
            for i in range(len(nums)):
                if not used[i]:
                    path.append(nums[i])
                    used[i] = 1
                    backtrack(used, path)
                    path.pop()
                    used[i] = 0
        backtrack(used, [])
        return res

Solution 2 : échanges en place

Variante sans used ni path : le préfixe nums[:first] est la partie déjà fixée, et le suffixe nums[first:] contient exactement les éléments encore disponibles. Pour fixer la position first, on y amène chaque élément du suffixe par un échange, on descend, puis on refait l'échange pour restaurer le tableau.

solution_2.py

class Solution:
    def permute(self, nums: list[int]) -> list[list[int]]:
        res = []
        def backtrack(first):
            if first == len(nums):
                res.append(nums[:])
                return
            for i in range(first, len(nums)):
                nums[first], nums[i] = nums[i], nums[first]
                backtrack(first + 1)
                nums[first], nums[i] = nums[i], nums[first]
        backtrack(0)
        return res

Elle évite la boucle sur des indices déjà utilisés (à la profondeur k, la solution 1 parcourt encore les n indices, dont k sont pris). Les deux versions renvoient exactement les n! permutations attendues (comparées à itertools.permutations sur quelques centaines de tableaux aléatoires) ; l'ordre de sortie diffère légèrement.

Complexité

Temps et espace de sortie O(n · n!) : n! permutations de longueur n à copier, ce qui est optimal. Espace auxiliaire O(n) (pile de récursion, plus used et path pour la solution 1).

À retenir

  • Subsets : on choisit si on prend chaque élément (start croissant). Permutations : on choisit quel élément vient ensuite (tous les indices libres).
  • Marquer les éléments utilisés avec un tableau used, ou les tenir dans un suffixe par échanges.
  • Variante à connaître : Permutations II (#47), avec doublons : trier, puis sauter nums[i] si nums[i] == nums[i − 1] et que nums[i − 1] n'est pas utilisé.

Subsets

16 Oct 2026 #78 · Medium ↗ récursion backtracking python

Le problème

Étant donné un tableau nums d'entiers distincts, renvoyer tous ses sous-ensembles (l'ensemble des parties), dans n'importe quel ordre. Pour [1, 2, 3], il y en a 2³ = 8, de [] à [1, 2, 3].

L'idée clé

Chaque élément est soit pris, soit laissé : deux choix indépendants par élément, d'où 2n sous-ensembles. Les trois solutions ci-dessous sont trois façons de parcourir cet arbre de choix binaires.

Solution 1 : récursion sur la queue de la liste

Ma version : les sous-ensembles de l sont ceux de l[1:], plus chacun d'eux complété par l[0]. Elle construit le résultat en remontant, sans état partagé à annuler.

solution_1.py

class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        def aux(l):
            if len(l) == 0:
                return [[]]
            if len(l) == 1:
                return [[],l]
            else:
                res = []
                rec = aux(l[1:])
                for sub in rec:
                    res.append(sub)
                    res.append([l[0]] + sub)
                return res
        res = aux(nums)
        return res

J'ai retiré un print de débogage qui affichait chaque appel récursif : sur LeetCode, il ralentit fortement la soumission. Le cas len(l) == 1 est redondant, puisque le cas de base [[]] suffit à le produire. Enfin, chaque l[1:] recopie la liste, ce qui reste négligeable devant la taille de la sortie.

Solution 2 (plus usuelle en entretien) : backtracking

Le patron que l'on retrouve dans Permutations, Combination Sum ou Palindrome Partitioning : chaque nœud de l'arbre est un sous-ensemble, on l'ajoute au résultat dès qu'on l'atteint, puis on essaie d'ajouter chaque élément suivant (indices croissants pour ne jamais produire deux fois le même ensemble).

solution_2.py

class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        res, path = [], []
        def backtrack(start):
            res.append(path[:])
            for i in range(start, len(nums)):
                path.append(nums[i])
                backtrack(i + 1)
                path.pop()
        backtrack(0)
        return res

Solution 3 : construction itérative

Même idée que la solution 1, mais sans récursion : on part de [[]] et, pour chaque élément, on double la liste en ajoutant une copie de chaque sous-ensemble existant complétée par cet élément.

solution_3.py

class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        res = [[]]
        for x in nums:
            res += [sub + [x] for sub in res]
        return res

Les trois versions renvoient exactement les 2n sous-ensembles attendus (comparés à itertools.combinations sur quelques centaines de tableaux aléatoires) ; seul l'ordre diffère.

Complexité

Temps et espace de sortie O(n · 2n) pour les trois : il y a 2n sous-ensembles de taille moyenne n / 2, à construire un par un. Aucune solution ne peut faire mieux, puisque c'est la taille de la réponse. Pile de récursion O(n) pour les solutions 1 et 2.

À retenir

  • « Tous les sous-ensembles » : 2n résultats, une décision binaire par élément.
  • Le backtracking avec start croissant évite les doublons sans avoir à les filtrer.
  • Penser à retirer les print de débogage avant de soumettre.
  • Variante à connaître : Subsets II (#90), avec doublons dans nums : trier, puis sauter nums[i] == nums[i − 1] quand i > start.

Unique Paths

16 Oct 2026 #62 · Medium ↗ programmation dynamique combinatoire python

Le problème

Un robot part du coin haut-gauche d'une grille m × n et doit atteindre le coin bas-droit en ne se déplaçant que vers la droite ou vers le bas. Combien de chemins distincts existe-t-il ?

L'idée clé

On ne peut arriver sur la case (i, j) que depuis celle du dessus ou celle de gauche. Le nombre de chemins vers (i, j) est donc la somme des deux : dp[i][j] = dp[i−1][j] + dp[i][j−1]. La première ligne et la première colonne valent 1 : il n'y a qu'une façon de les atteindre (tout droit).

Solution 1 : table DP 2D

Ma version, qui est aussi la formulation de référence : initialiser les bords à 1, puis remplir la table ligne par ligne.

solution_1.py

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        dp = [[0]*n for _ in range(m)]
        for i in range(n):
            dp[0][i] = 1
        for i in range(m):
            dp[i][0] = 1

        for i in range(1,m):
            for j in range(1,n):
                dp[i][j] = dp[i-1][j] + dp[i][j-1]

        return dp[m-1][n-1]

Solution 2 : une seule ligne, espace O(n)

Chaque ligne ne dépend que de la précédente. En gardant une seule ligne row, au moment de calculer row[j], elle contient encore l'ancienne valeur (celle du dessus) et row[j − 1] vient d'être mise à jour (celle de gauche) : il suffit de faire row[j] += row[j − 1].

solution_2.py

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        row = [1] * n
        for _ in range(1, m):
            for j in range(1, n):
                row[j] += row[j - 1]
        return row[-1]

Solution 3 : formule combinatoire

Tout chemin fait exactement m − 1 pas vers le bas et n − 1 pas vers la droite, soit m + n − 2 pas au total. Un chemin est entièrement déterminé par le choix des positions des pas « bas » parmi ces m + n − 2 : la réponse est le coefficient binomial C(m + n − 2, m − 1).

solution_3.py

from math import comb

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        return comb(m + n - 2, m - 1)

Les trois solutions donnent le même résultat pour toutes les grilles jusqu'à 14 × 14 (et sur 100 × 100). La table DP n'est d'ailleurs rien d'autre que le triangle de Pascal penché.

À retenir

  • Compter des chemins dans une grille : dp[i][j] = somme des cases depuis lesquelles on peut arriver.
  • Quand une ligne ne dépend que de la précédente, passer d'une table 2D à une seule ligne.
  • Si la question ne porte que sur un dénombrement sans obstacles, chercher une formule fermée. En entretien, présenter d'abord la DP puis mentionner la formule.
  • Variante à connaître : Unique Paths II (#63), avec obstacles, où une case bloquée vaut 0 et la formule ne s'applique plus.

Palindrome Partitioning

16 Oct 2026 #131 · Medium ↗ backtracking programmation dynamique chaînes python

Le problème

Découper une chaîne s en morceaux consécutifs qui soient tous des palindromes, et renvoyer toutes les découpes possibles. Pour "aab" : [["a","a","b"], ["aa","b"]].

L'idée clé

On construit la découpe de gauche à droite. Depuis la position start, on essaie chaque préfixe s[start:i+1] ; s'il est palindrome, on le garde et on découpe récursivement la suite à partir de i + 1. Quand start atteint la fin de la chaîne, la découpe courante est complète. Les préfixes non palindromes coupent la branche immédiatement.

"aab"
├─ "a"   reste "ab"
│   ├─ "a"   reste "b"
│   │   └─ "b"   → ["a", "a", "b"] ✓
│   └─ "ab"  ✗ pas un palindrome
├─ "aa"  reste "b"
│   └─ "b"   → ["aa", "b"] ✓
└─ "aab" ✗ pas un palindrome

Solution 1 : backtracking avec test par inversion

solution_1.py

class Solution:
    def partition(self, s: str) -> list[list[str]]:
        res = []
        def backtrack(start, partition, length):
            if length == len(s):
                res.append(list(partition))
            for i in range(start, len(s)):
                cand = s[start:i+1]
                if cand == cand[::-1]:
                    partition.append(cand)
                    length+=i+1-start
                    backtrack(i+1, partition, length)
                    partition.pop()
                    length-=i+1-start
        backtrack(0, [], 0)
        return res

Correcte. Deux remarques : length vaut toujours exactement start (les morceaux couvrent s[0:start]), on peut donc s'en passer et tester start == len(s). Et la copie list(partition) est indispensable : sans elle, res contiendrait plusieurs références vers la même liste, vidée à la fin par les pop().

Solution 2 (plus usuelle) : palindromes précalculés

Le test cand == cand[::-1] coûte O(n) et est refait pour les mêmes sous-chaînes dans de nombreuses branches. La version classique précalcule une table is_pal[i][j] par programmation dynamique : s[i..j] est un palindrome si ses extrémités sont égales et que l'intérieur s[i+1..j-1] en est un. Chaque test devient alors un lookup en O(1).

solution_2.py

class Solution:
    def partition(self, s: str) -> list[list[str]]:
        n = len(s)
        is_pal = [[False] * n for _ in range(n)]
        for i in range(n - 1, -1, -1):
            for j in range(i, n):
                is_pal[i][j] = s[i] == s[j] and (j - i < 2 or is_pal[i + 1][j - 1])
        res, path = [], []
        def backtrack(start):
            if start == n:
                res.append(path[:])
                return
            for end in range(start, n):
                if is_pal[start][end]:
                    path.append(s[start:end + 1])
                    backtrack(end + 1)
                    path.pop()
        backtrack(0)
        return res

i est parcouru à l'envers pour que is_pal[i + 1][j - 1] soit déjà calculé. Les deux solutions renvoient les mêmes découpes qu'une énumération brute-force des 2n−1 découpes possibles, sur quelques milliers de chaînes aléatoires.

Complexité

Il y a jusqu'à 2n−1 découpes valides (cas "aaaa…"), chacune copiée en O(n) : temps O(n · 2n) dans le pire cas pour les deux solutions. La solution 2 ajoute O(n²) de précalcul (temps et espace) mais rend chaque test de palindrome constant. Pile de récursion : O(n).

À retenir

  • « Toutes les découpes / combinaisons » : backtracking sur la position de départ.
  • Toujours ajouter une copie du chemin courant au résultat.
  • Quand le même sous-problème (« s[i..j] est-il un palindrome ? ») revient dans plusieurs branches, le précalculer.

Word Search

16 Oct 2026 #79 · Medium ↗ backtracking dfs matrice python

Le problème

Étant donnée une grille de lettres m × n et un mot, dire si le mot peut être formé en reliant des cases adjacentes (haut, bas, gauche, droite), sans réutiliser deux fois la même case.

L'idée clé

On essaie chaque case comme point de départ, puis on prolonge le chemin lettre par lettre par un parcours en profondeur (DFS) : à l'étape k, on cherche parmi les 4 voisins une case non utilisée qui porte word[k]. On marque la case avant de descendre et on la libère en remontant : c'est le même patron choisir → explorer → annuler que pour N-Queens.

Solution 1 : matrice used et exploration des voisins

Ma version : une matrice used mémorise les cases du chemin courant, et la fonction récursive regarde les voisins de la case courante avant d'y descendre.

solution_1.py

class Solution:
    def exist(self, board: list[list[str]], word: str) -> bool:
        m, n = len(board), len(board[0])
        direction = [(-1,0), (1,0), (0, -1), (0,1)]
        used = [[0]*n for _ in range(m)]
        def bfs(i,j, k, used):
            if k == len(word):
                return True
            for d1, d2 in direction:
                if 0<= i+d1 < m and 0<= j+d2 < n:
                    if not used[i+d1][j+d2]:
                        if board[i+d1][j+d2] == word[k]:
                            used[i+d1][j+d2] = 1
                            res = bfs(i+d1, j+d2, k+1, used)
                            used[i+d1][j+d2] = 0
                            if res:
                                return True
            return False

        for i in range(m):
            for j in range(n):
                if board[i][j] == word[0]:
                    used[i][j] = 1
                    res = bfs(i,j, 1, used)
                    if res:
                        return True
                    used[i][j] = 0
        return False

Correction : ma première version appelait bfs(i, j, [board[i][j]], used), c'est-à-dire avec une liste comme indice k, ce qui lève un TypeError dès que word[k] est évalué. La première lettre étant déjà vérifiée, la recherche doit reprendre à l'indice k = 1. Autre remarque : malgré son nom, bfs fait un parcours en profondeur (DFS), pas en largeur.

Solution 2 (plus usuelle) : marquage en place dans la grille

Variante courante : vérifier la case à l'entrée de l'appel récursif plutôt que ses voisins, et marquer la case visitée directement dans board en remplaçant temporairement sa lettre par '#'. Plus besoin de matrice used, ni de traiter la première lettre à part.

solution_2.py

class Solution:
    def exist(self, board: list[list[str]], word: str) -> bool:
        m, n = len(board), len(board[0])
        def dfs(i, j, k):
            if k == len(word):
                return True
            if not (0 <= i < m and 0 <= j < n) or board[i][j] != word[k]:
                return False
            tmp, board[i][j] = board[i][j], '#'
            found = (dfs(i + 1, j, k + 1) or dfs(i - 1, j, k + 1)
                     or dfs(i, j + 1, k + 1) or dfs(i, j - 1, k + 1))
            board[i][j] = tmp
            return found
        return any(dfs(i, j, 0) for i in range(m) for j in range(n))

Les deux versions donnent les mêmes résultats qu'une recherche brute-force sur quelques milliers de grilles aléatoires. La seconde modifie la grille d'entrée pendant la recherche mais la restaure toujours avant de rendre la main.

Complexité

Temps O(m · n · 3L) avec L = len(word) : chaque case peut être un départ, puis chaque étape a au plus 3 voisins nouveaux (on ne revient pas sur la case d'où l'on vient). Espace O(L) pour la pile de récursion, plus O(m · n) pour used dans la solution 1.

À retenir

  • Chemin dans une grille sans répétition de case : DFS + backtracking, pas BFS (le BFS ne sait pas « dé-visiter » une case propre à un chemin).
  • Marquer en place ('#') puis restaurer évite une structure auxiliaire.
  • Tester la validité à l'entrée de la récursion simplifie le code (bornes, lettre et visite au même endroit).
  • Élagages utiles en pratique : abandonner si le mot est plus long que m · n, ou si une lettre y apparaît plus souvent que dans la grille.

Maximal Square

15 Oct 2026 #221 · Medium ↗ programmation dynamique matrice python

Le problème

Dans une matrice binaire m × n remplie de "0" et de "1", trouver le plus grand carré ne contenant que des 1 et renvoyer son aire.

L'idée clé

On note dp[i][j] le côté du plus grand carré de 1 ancré en (i, j). Un carré de côté k ancré en (i, j) existe si et seulement si la case vaut 1 et ses trois voisines (dans la direction opposée à l'ancre) portent chacune un carré de côté au moins k − 1. Le plus petit des trois limite donc la taille :

dp[i][j] = 1 + min(voisin vertical, voisin horizontal, voisin diagonal) si matrix[i][j] == "1", sinon 0.

La réponse est max(dp)². Ci-dessous l'exemple 1 de LeetCode, avec la table dp de la solution 2 (ancre en bas à droite) : le maximum vaut 2, d'où une aire de 4.

Solution 1 : ancre en haut à gauche, parcours depuis le coin bas-droit

Ma version : dp[j][i] est le côté du plus grand carré dont (j, i) est le coin haut-gauche. Il dépend donc des cases du dessous, de droite et en diagonale bas-droite, d'où un parcours qui part du coin bas-droit. La dernière ligne et la dernière colonne sont initialisées à part, car elles n'ont pas de voisins de ce côté.

solution_1.py

class Solution:
    def maximalSquare(self, matrix: list[list[str]]) -> int:
        m,n = len(matrix), len(matrix[0])
        dp = [[0]*n for _ in range(m)]
        maxi = 0
        for i in range(n):
            dp[m-1][i] = int(matrix[m-1][i])
            if maxi < dp[m-1][i]:
                maxi = dp[m-1][i]
        for i in range(m):
            dp[i][n-1] = int(matrix[i][n-1])
            if maxi < dp[i][n-1]:
                maxi = dp[i][n-1]
        for i in range(n-2, -1, -1):
            for j in range(m-2, -1, -1):
                dp[j][i] = int(matrix[j][i])*(min(dp[j+1][i], dp[j][i+1], dp[j+1][i+1]) + 1)
                if maxi < dp[j][i]:
                    maxi = dp[j][i]
        return maxi**2

Le produit int(matrix[j][i]) * (…) remplace élégamment le if : une case à 0 annule le résultat. Attention à l'ordre des indices : la boucle externe porte sur les colonnes (i) et l'interne sur les lignes (j), ce qui est correct mais inhabituel à relire.

Solution 2 (plus usuelle) : ancre en bas à droite, avec bordure de zéros

La formulation la plus courante prend (i, j) comme coin bas-droit du carré : on dépend alors des cases du haut, de gauche et en diagonale haut-gauche, et on parcourt la matrice dans l'ordre naturel. En allouant une table (m + 1) × (n + 1), la ligne 0 et la colonne 0 servent de bordure de zéros : plus besoin d'initialiser la première ligne et la première colonne à part.

solution_2.py

class Solution:
    def maximalSquare(self, matrix: list[list[str]]) -> int:
        m, n = len(matrix), len(matrix[0])
        dp = [[0] * (n + 1) for _ in range(m + 1)]
        side = 0
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if matrix[i - 1][j - 1] == '1':
                    dp[i][j] = 1 + min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
                    side = max(side, dp[i][j])
        return side * side

Les deux solutions sont équivalentes (vérifiées contre une recherche brute-force sur quelques milliers de matrices aléatoires) ; la seconde est simplement plus courte et sans cas particuliers.

Complexité

Temps O(m · n) pour les deux : chaque case est calculée une fois, en O(1). Espace O(m · n) pour la table dp. Comme dp[i][j] ne dépend que de la ligne courante et de la précédente, on peut ne garder qu'une ligne et descendre à O(n).

À retenir

  • Grille + « plus grand carré / chemin / rectangle » : chercher une récurrence sur les voisins déjà calculés.
  • Le min des trois voisins : le carré est limité par son voisin le plus « faible ».
  • Une bordure de zéros (table de taille (m + 1) × (n + 1)) supprime les initialisations spéciales.
  • Renvoyer l'aire, pas le côté.

Valid Parentheses

15 Oct 2026 #20 · Easy ↗ pile hashmap python

Le problème

Une chaîne ne contient que les caractères ()[]{}. Elle est valide si chaque ouvrante est fermée par une fermante du même type, et dans le bon ordre : "{[]}()" est valide, "([)]" ne l'est pas.

L'idée clé

La dernière parenthèse ouverte est la première qui doit être fermée : c'est exactement le comportement d'une pile (LIFO). On empile chaque ouvrante ; à chaque fermante, le sommet de la pile doit être l'ouvrante correspondante, qu'on dépile alors. Un dictionnaire fermante → ouvrante rend la correspondance immédiate.

solution.py

class Solution:
    def isValid(self, s: str) -> bool:
        queue = []
        d = {')':'(', '}':'{', ']':'['}
        for char in s:
            if char in d:
                if not queue:
                    return False
                if d[char] != queue[-1]:
                    return False
                queue.pop()
            else:
                queue.append(char)
        return not queue

Malgré son nom, queue est bien utilisée comme une pile : append et pop agissent tous deux sur la fin de la liste, en O(1). Trois cas mènent à False : une fermante alors que la pile est vide (")("), une fermante du mauvais type ("(]"), et des ouvrantes restées sans partenaire à la fin ("(("), d'où le return not queue.

À retenir

  • Structure imbriquée, « le dernier ouvert est le premier fermé » : penser pile.
  • Un dictionnaire indexé par la fermante évite une cascade de if.
  • Petite optimisation possible : une chaîne de longueur impaire ne peut jamais être valide.

N-Queens I & II

15 Oct 2026 #51 · Hard ↗ #52 · Hard ↗ backtracking python

Le problème

Placer n reines sur un échiquier n × n sans qu'aucune ne puisse en attaquer une autre : jamais deux reines sur la même ligne, la même colonne ou la même diagonale. La version I demande de renvoyer toutes les configurations (sous forme de lignes ".Q.."), la version II seulement leur nombre.

L'idée clé

Comme il y a exactement une reine par ligne, on place les reines ligne par ligne : la contrainte de ligne est satisfaite par construction. À chaque ligne, on essaie chaque colonne encore libre, on descend récursivement, et on revient en arrière (backtrack) quand plus rien n'est possible.

Reste à savoir rapidement si une case (line, i) est attaquée. Sur une même diagonale \, la quantité line − i est constante ; sur une même anti-diagonale /, c'est line + i qui est constante. Une diagonale entière se résume donc à un seul entier.

Solution 1 : matrice d'occupation

Ma première approche : maintenir une matrice occ qui marque les cases attaquées. Quand je pose une reine, je marque sa colonne et ses deux diagonales vers le bas (les lignes du dessus sont déjà remplies, inutile d'y toucher), puis je passe des copies de la grille et de occ à l'appel récursif, ce qui évite d'avoir à « dé-marquer » au retour.

solution_1.py

class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        res = []
        grid = [['.' for _ in range(n)] for _ in range(n)]
        occ = [[0]*n for _ in range(n)]
        def backtrack(line, grid, occ):
            if line == n:
                grid = [''.join(l) for l in grid]
                res.append(grid)
                return
            for i in range(n):
                if occ[line][i]:
                    continue
                grid_new = [row[:] for row in grid]
                occ_new = [row[:] for row in occ]
                grid_new[line][i] = 'Q'
                for j in range(n):
                    occ_new[j][i] = 1
                for j in range(min(n-line,n-i)):
                    occ_new[line+j][i+j] = 1
                for j in range(min(n-line,i+1)):
                    occ_new[line+j][i-j] = 1

                backtrack(line+1, grid_new, occ_new)
        backtrack(0,grid,occ)
        return res

Correcte, mais coûteuse : chaque tentative recopie deux matrices n × n, soit un travail en O(n²) par nœud de l'arbre de recherche, et autant de mémoire par niveau de récursion.

Solution 2 : trois ensembles et backtracking en place

En utilisant l'observation sur les diagonales, l'état complet tient dans trois ensembles : les colonnes prises, les valeurs de line + i prises et les valeurs de line − i prises. Tester une case devient trois lookups en O(1), et au lieu de copier, on annule le coup après l'appel récursif.

solution_2.py

class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        res = []
        grid = [['.' for _ in range(n)] for _ in range(n)]
        diag_left = set()
        diag_right = set()
        cols = set()
        def backtrack(line, grid, diag_left, diag_right, cols):
            if line == n:
                grid = [''.join(l) for l in grid]
                res.append(grid)
                return
            for i in range(n):
                if line + i in diag_left or line - i in diag_right or i in cols:
                    continue
                diag_left.add(line + i)
                diag_right.add(line - i)
                cols.add(i)
                grid[line][i] = 'Q'
                backtrack(line+1, grid, diag_left, diag_right, cols)
                diag_left.remove(line + i)
                diag_right.remove(line - i)
                cols.remove(i)
                grid[line][i] = '.'
        backtrack(0,grid, diag_left, diag_right, cols)
        return res

Le schéma choisir → explorer → annuler est le patron classique du backtracking. La grille n'est convertie en chaînes (''.join) qu'au moment où une solution complète est trouvée, ce qui revient à en prendre un instantané.

N-Queens II : compter au lieu de lister

Même parcours, mais on n'a plus besoin de la grille : on incrémente un compteur à chaque feuille valide. Le nonlocal permet de modifier la variable res de la fonction englobante depuis la fonction imbriquée.

n_queens_ii.py

class Solution:
    def totalNQueens(self, n: int) -> int:
        res = 0
        diag_left = set()
        diag_right = set()
        cols = set()
        def backtrack(line, diag_left, diag_right, cols):
            if line == n:
                nonlocal res
                res += 1
                return
            for i in range(n):
                if line + i in diag_left or line - i in diag_right or i in cols:
                    continue
                diag_left.add(line + i)
                diag_right.add(line - i)
                cols.add(i)

                backtrack(line+1, diag_left, diag_right, cols)

                diag_left.remove(line + i)
                diag_right.remove(line - i)
                cols.remove(i)

        backtrack(0, diag_left, diag_right, cols)
        return res

O(n!) est une borne supérieure : la ligne k offre au plus n − k colonnes libres, et l'élagage par les diagonales réduit fortement l'arbre en pratique (pour n = 8, il n'y a que 92 solutions).

À retenir

  • Une diagonale se code par un seul entier : r − c pour \, r + c pour /. L'astuce resservira pour tous les problèmes de grille.
  • Plutôt que de copier l'état à chaque appel, le modifier en place puis l'annuler au retour.
  • Quand seul le nombre de solutions compte, supprimer tout ce qui sert à construire la sortie.
